# ZamCan Academy — premium visual identity directive

## Logo
Do NOT use a plain letter, generic Z, unmodified graduation cap or stock icon as the final logo. Create a distinct, original, professionally drawn academy emblem combining learning and computing, recognizable at 48dp. Produce adaptive Android foreground/background, monochrome themed icon, high-res store icon, splash/wordmark and light/dark variants. Keep a single coherent mark across the app; do not imply external accreditation through a seal. Review and preserve any superior existing artwork first. Generated concept imagery is a reference, not an automatically approved production asset.

## Design tokens and restraint
Premium deep navy/ink (#0B1025), elevated navy (#151D38), restrained violet (#7556DD), blue (#3878E8), warm gold (#E8B95C), success green (#22B980), text white (#F6F7FF); accessible light theme with equivalent hierarchy. Ensure WCAG-level contrast, readable 14sp+ body, 48dp touch targets, scalable typography. Avoid excessive neon/glow, heavy gradients, tiny text, crowded buttons or web-card appearance. Gold is an accent, not an entire screen treatment.

## App navigation
Two dominant home destinations: Code Studio and Learning Academy. Secondary destinations (projects, exams, achievements, certificates, settings) are within appropriate navigation, not competing home sections. Polished short wordmark boot; no lengthy splash.

## Code Studio
Syntax colors for keywords, types, strings, numbers, comments, preprocessor directives, errors; accessible palettes; 4-space indentation, line numbers, tabs, brace matching, actual compiler stdout/stderr and exit status. A pretty output pane is not evidence of real execution.

## Learning
Segmented progress, stage-by-stage deep lessons, token-by-token explanations, interactive recall and quizzes, tasteful success states, clearly visible progress, offline indicators. Static project previews must be labeled, distinct from actual compiler output.

## Ads
User wants a small ad attached to the screen: use anchored adaptive **banner** ads, not full-screen interstitials. Never fake an AdMob ad with an illustrative graphic. Only show real ads after SDK and consent setup; use test IDs during development. Reserve a stable layout slot and hide when unavailable; do not cover code editor, keyboard, terminal, timed exam, certificate screens or learning text. Check Google policies and privacy requirements before production.

## Acceptance
Review on 360dp small phone and tablet, dark and light, portrait/landscape where supported, TalkBack, large fonts and reduced motion. Export final logo assets as actual Android resources, document asset origin/licensing, and capture screenshots from the real APK. Do not claim that concept images are implemented.
