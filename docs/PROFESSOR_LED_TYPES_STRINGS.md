# Professor-led learning: exhaustive types, strings, constants, and illustrations

## Intent and originality
The supplied screenshots show an instructor speaking conversationally to learners, contextual illustrations, progressive segmented stages, end-of-course encouragement, exam instructions, performance feedback, and a certificate transition. Create a consistent **original fictional CodeLab Professor** with distinct original appearance and voice; do not impersonate Bjarne Stroustrup, copy his likeness or imply endorsement. Avoid repeating a mascot on every screen: illustrations must clarify a concept, demonstrate a mental model, or motivate a transition. Provide descriptive alt text and a reduced-motion mode. All diagrams must be technically accurate and accessible.

## Professor script grammar
Each stage contains: (1) a concise first-person instructor explanation addressed to learner, (2) why the concept matters, (3) precise terminology and grammar, (4) annotated working example, (5) predicted output and actual test expectation, (6) a visual mental model, (7) common misconceptions and real compiler diagnostics, (8) Try/Check interactive experiment, (9) feedback and next stage. Use a friendly serious university instructor voice, not a fictional quote attributed to a real computer scientist. Avoid patronizing congratulations. Never fabricate program output or test results.

## Types and variables: mandatory coverage
- Object, value, variable, identifier, declaration, definition, initialization, assignment, storage duration, lifetime, scope, linkage, type qualifiers, lvalues/rvalues at appropriate levels.
- C17: `char`, `signed char`, `unsigned char`, `short`, `unsigned short`, `int`, `unsigned int`, `long`, `unsigned long`, `long long`, `unsigned long long`, `_Bool` (with `<stdbool.h>` `bool`), `float`, `double`, `long double`, `void`, pointers, arrays, functions, structs, unions, enums, `typedef` aliases, fixed-width integers in `<stdint.h>` where available, `size_t`, `ptrdiff_t`, `const`, `volatile`, `restrict`, `static`, `extern`, `register` in historical context. Explain implementation-dependent sizes/ranges, `sizeof`, `limits.h`, `float.h`, numeric precision, overflow, conversions, format specifiers, and portable code.
- C++17: `bool`, `char`, `signed/unsigned char`, `wchar_t`, `char16_t`, `char32_t`, integral/floating families, `nullptr_t`, `auto`, `decltype`, references, `const`, `constexpr`, `static`, `enum class`, class/struct, `std::size_t`, `std::int32_t` where supported, and `std::string`/containers. Explain what differs from C.
- `float` vs `double` vs `long double`: binary floating-point approximation, literals (`3.5f`, `3.5`, `3.5L`), typical but not guaranteed precision/size, formatting and safe comparisons. Demonstrate `0.1 + 0.2` and explain why financial accounting generally needs integer minor units or decimal arithmetic, not naive binary floating-point.
- Literals and constants: integer bases (decimal/octal/hex; binary literal in C++14+, not standard C17), integer suffixes U/L/LL, floating suffixes F/L, character and string literals, escapes, boolean, null pointer, `const` vs `constexpr`, `#define` macros vs typed constants, enumerators, symbolic constants, `static const`, C compound literals, scope and evaluation rules. Distinguish immutable objects from compile-time constant expressions.

## Strings: mandatory deep coverage
1. What a string is versus a character: `'A'` vs `"A"`; encoding and bytes; escape sequences (`\\n`, `\\t`, `\\0`, `\\\\`, quotes); raw string literals in C++.
2. C strings as NUL-terminated arrays of `char`; declaration `char name[] = "Asha";`, explicit array initialization, storage and terminator, `sizeof` vs `strlen`, indexing and bounds, string literals and nonmodifiable literal storage.
3. C input/output: `printf("%s", name)`, `fgets`, newline removal, input limits, why unbounded `scanf("%s", ...)` is dangerous; format specifiers and `<string.h>` functions `strlen`, `strcmp`, `strchr`, `strstr`, `memcpy`, `strncpy` caveats, `snprintf` and concatenation with capacity checks.
4. C++ `std::string`: construction, `std::getline`, `size`, `empty`, `at` vs `[]`, concatenation, comparison, `find`, `substr`, references/iterators, conversion to C APIs with `c_str()`; ownership and lifetime; `std::string_view` (C++17) nonowning semantics and dangling-view hazards.
5. String representations: C narrow/wide strings, UTF-8 vs Unicode code points, `wchar_t`/wide strings, UTF-16/UTF-32 and `char16_t`/`char32_t` in C++, locale, multibyte encodings and why byte count differs from user-visible characters. Do not imply `std::string` automatically understands Unicode grapheme clusters. Contrast char arrays, string literals, `std::string`, `std::string_view`, and string streams; teach where each is appropriate.
6. Advanced practical labs: safe name input, record search, case-sensitive comparisons, tokenization pitfalls, validating a user-entered student ID, and building a formatted report. Explicitly separate educational login demonstration from secure production authentication.

## Detailed visual sequence example
Professor: “A single character and a person's name are not the same kind of value. Watch the quote marks.” Show a memory-cell illustration: `char grade = 'A';` versus `char name[] = "Asha";` with five labeled byte cells A | s | h | a | \\0. Show `sizeof(name) == 5` and `strlen(name) == 4` in a C17 example. Next, demonstrate `std::string name = "Asha";` in C++17, explain that it manages storage and can grow, then contrast `std::string_view` ownership. Follow with editable examples, compiler-backed checks, and a student challenge. Never present an image as proof of code execution.
