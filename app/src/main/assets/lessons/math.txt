MATHEMATICS AS ALGORITHMS

COMPOUND INTEREST
Problem: start with 1000, increase by 10% once each year, stop when the amount is strictly greater than 2000.
Algorithm: amount = 1000, years = 0; while amount <= 2000, multiply by 1.10 and increment years. Compare after each completed year. With this model the first crossing is year 8 (approximately 2143.59).

double amount = 1000.0;
int years = 0;
while (amount <= 2000.0) {
    amount *= 1.10;
    ++years;
}

Why <= instead of <: the requirement says strictly greater than 2000. Why 1.10: the new amount includes the original 100% plus 10%. Floating-point amounts are approximate; this is a mathematical teaching model, not a financial product or a money-rounding policy. Test 0% growth separately: the loop would never terminate without a progress check. Independent task: accept a validated starting amount, target, and positive growth rate.

CELSIUS TO FAHRENHEIT
F = (9.0 / 5.0) * C + 32. The decimal operands force floating-point division. In C/C++, 9 / 5 with integer operands evaluates to 1, producing the wrong scale. Test C=0 → F=32, C=100 → F=212, and C=-40 → F=-40. Reject non-finite input. Independent task: derive and test the inverse transformation.

NUMBER SYSTEMS
For a nonnegative integer, repeatedly divide by base b and record remainders. Read the remainders in reverse. Example: 13 / 2 gives quotient 6 remainder 1; 6 / 2 → 3 remainder 0; 3 / 2 → 1 remainder 1; 1 / 2 → 0 remainder 1. Reverse gives binary 1101. Zero needs an explicit single-zero result. Validate 2 <= b <= 16 and map remainders 10–15 to A–F. Test 0, 1, 15, and 16.

GRADES AND DECISION TABLES
Define the policy before code. This exercise uses integer scores 0–100 and an illustrative pass threshold of 50. Scores below 0 or above 100 are invalid; 0–49 means retry; 50–100 means pass. Test the boundaries -1, 0, 49, 50, 100, and 101. This policy is not an institutional GPA scale.

SEARCH AND INVARIANTS
For a linear search, inspect each valid index from 0 to count-1. Return a matching index or a documented not-found result. Never use the not-found result as an array subscript. Tests: empty collection, first item, last item, absent value, and duplicates under a documented policy.
