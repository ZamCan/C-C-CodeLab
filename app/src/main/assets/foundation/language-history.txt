Why did C grow up alongside Unix?

Imagine moving an operating system to a computer with a different processor. Assembly instructions written for the first machine may have to be rewritten for the second.

At Bell Labs in the early 1970s, Dennis Ritchie developed C while working on Unix. C let the team express much of the system in a language that a compiler could translate for each machine. Hardware-specific parts still needed special care.

Look at the illustration. The function symbol on the C side stands for a way to divide a large job into named pieces. What changes when each piece must also manage its own data?
Why add classes?

In 1979 Bjarne Stroustrup began working on C with Classes. He wanted to organize complex programs using ideas from Simula while keeping the efficiency he valued in C. The name C++ followed in 1983.

Think of a bank account. In C, a structure can hold the balance and a separate function can update it. In C++, a class can keep the balance private and give callers a deposit operation. Both designs can solve the same problem. The class gives the author a language rule for controlling access.

C and C++ now have separate standards and libraries. Shared syntax helps you read both, but each source file needs the appropriate language mode.
Make C speak

Before you read the next paragraph, predict exactly what appears on screen.

    #include <stdio.h>
    int main(void) {
        printf("Hello, C!\n");
        return 0;
    }

The program prints Hello, C! and moves to a new line. The header declares printf. The parentheses in main(void) tell a C17 compiler that main takes no arguments. The braces surround the statements that run. Returning zero reports success.
Say it again in C++

    #include <iostream>
    int main() {
        std::cout << "Hello, C++!\n";
        return 0;
    }

Here the header provides the standard output stream. In std::cout, std names the namespace and :: selects cout from it. The << operator sends the string to the stream. As in C, the semicolon ends the statement.

Try changing only the greeting in each program. Predict which characters will change and whether the next output will begin on a new line.
